# AGENTS.md — building on full_stack_engine

This app runs on **full_stack_engine**: a Rust (actix-web + SQLite) full-stack
framework where **a struct is a feature**. One `#[model]` struct gives you the
table, migrations, compile-time-checked queries, admin pages, public pages, a
JSON API, permissions, row-level access rules, validation, relations, nesting,
many-to-many links and row actions. Hand-written code is for the rare flow a
model can't declare.

Read this file once, completely, before changing anything. It is the whole
reference; you should not need to read framework sources.

---

## 1. The workflow

1. **Model it** — add or change a struct in `src/models/<snake_case>.rs`
   (one struct per file, file name = snake_case of the struct name) and
   `pub mod` it in `src/models/mod.rs`.
2. **Migrate** — `fse migrate` (generates + applies a migration and refreshes
   the `.sqlx/` query cache). Never write or edit a migration by hand.
3. **Grant it** — give roles `{base}.read` / `{base}.write` in
   `define_roles!` (`src/lib.rs`). `{base}` = table name, or
   `permission = "..."`, or the parent's base for a nested model.
4. **Label it** — `locales/<lang>.json` → `models.{table}.title`,
   `.fields.{column}`, `.options.{enum_value}`, `.actions.{action}`.
5. **Test it** — `cargo test` (tests drive the real app, see §9).
6. **Only then hand-write** — `src/services/` for flows a model can't express.
   Never re-implement CRUD, auth, permissions, ownership or validation there.

`cargo run -- --routes` (or `fse routes`) prints every generated route with
the permission it requires — use it to check what exists.

### Commands

```
fse new <name>            # new app (blank, ready to run)
fse migrate               # after any model change
fse migrate --dry-run     # show the pending schema change
fse routes                # generated routes + permissions
cargo test                # everything, against the real stack
cargo clippy --all-targets   # must stay warning-free (deny(warnings))
cargo run                 # http://localhost:8080
cargo run -- --hash-password 'pw'   # Argon2 hash for a manual user row
```

With a child theme (`theme/`): `cd theme && bun install && bun run build`
before `cargo build` (the built `theme/dist` is embedded in the binary).

### Layout

```
src/models/      THE APP — #[model] structs + their hooks/actions
src/services/    hand-written routes (special cases only)
src/lib.rs       roles (define_roles!), themes(), app() builder
locales/*.json   labels + app texts (framework texts are built in)
migrations/      generated by `fse migrate` — never edit
.sqlx/           generated query cache — commit it
tests/           TestApp tests
theme/           optional child theme (Astro) — only for custom page design
```

## 2. A model

```rust
use crate::{chrono::NaiveDateTime, model, Cond, DbEnum, ModelHooks};
use crate::models::user::User;

#[derive(DbEnum, Debug, Clone, Copy, PartialEq, Eq)]
pub enum Status { Draft, Published }

#[model(owner = author_id, public_read = slug, api, hooks)]
pub struct Article {
    pub id: i64,                                   // every model: `id: i64`
    #[orm(references(User, on_delete = cascade))]
    pub author_id: i64,                            // owner: set from the signed-in user
    #[orm(relation = author_id)]
    #[ui(list)]                                    // list column: author's title
    pub author: Option<User>,
    #[ui(list, search, max = 120)]
    pub title: String,
    #[orm(unique)]
    #[ui(slug_from = title)]                       // empty → derived from title
    pub slug: String,
    #[ui(textarea)]
    pub body: Option<String>,
    #[orm(default = "draft")]
    #[ui(list, filter)]
    pub status: Status,
    #[orm(default = now)]
    #[ui(list, format = date)]
    pub created_at: NaiveDateTime,
}

impl ModelHooks for Article {
    // Public pages + public API show published rows only.
    fn public_scope() -> Option<Cond> {
        Some(Article::STATUS.eq(Status::Published))
    }
}
```

That struct gives: `/admin/articles` (list, search, status filter, create,
edit, delete — authors see only their own, admins all), `/articles` +
`/articles/{slug}` (public, published only), `/api/articles` (JSON),
permissions `articles.read` / `articles.write`.

Column types: `i64`, `f64`, `bool`, `String`, `NaiveDateTime`, `NaiveDate`,
`NaiveTime`, `Uuid`, `DbEnum` enums, `Option<_>` of those, `#[orm(json)]`
fields. `#[orm(...)]` is the database (`unique`, `index`, `default = ...`,
`references(Target, on_delete = cascade|set_null|restrict)`, `text`, `json`,
struct-level `#[orm(unique(a, b))]` / `#[orm(index(a, b))]`). `#[ui(...)]`
and `#[model(...)]` are the app. Mistakes are compile errors with a fix in
the message; cross-model mistakes fail at boot (and in `cargo test`).

### `#[model(...)]` options

| option | effect |
|---|---|
| *(none)* | admin CRUD at `/admin/{table}` |
| `path = "x"` | admin pages at `/x` instead (nested: the segment under the parent) |
| `permission = "x"` | permission base `x.read` / `x.write` (default: table, or parent's) |
| `public_read` / `public_read = col` | public list `/{table}` + detail `/{table}/{col}` (col unique) |
| `api` | JSON API `/api/{table}`, `/api/{table}/{key}` (public with `public_read`, else needs read permission) |
| `owner = col` | rows belong to the user in `col` (`i64` user id): non-admins see/change only their own; set from the signed-in user on create, never a form field |
| `parent = col` | nested under the model `col` references: routes `{parent base}/{parent_id}/{segment}`, visible only under a parent the user can see, created under the URL's parent |
| `actions(a, b)` | row actions: `POST {base}/{id}/actions/a` → `async fn a(&self, cx: ActionCx<'_>) -> AppResult<()>` on the struct |
| `link = col` | this struct is a many-to-many join table (see §5) |
| `order_by = "-col"` | default list order (`-` = descending); default `-created_at`, else `-id` |
| `per_page = n` | default page size (1–100, default 20) |
| `title_field = col` | the column other rows show for this one (default: first visible text column) |
| `hooks` | you write `impl ModelHooks for X` (§3); without it all hooks are defaults |
| `no_create` / `no_edit` / `no_delete` | drop that generated endpoint |
| `disabled` | register metadata only — no routes (still usable as a relation/link target) |

### `#[ui(...)]` on a column

| flag | effect |
|---|---|
| `list` | column in the list table (if no column has it: all visible columns) |
| `search` | the list's search box matches it (String) |
| `filter` | list filter: dropdown (enum/bool), substring (text), `{col}_from`/`{col}_to` (number, date, timestamp); `filter = exact\|contains\|range` to choose |
| `required` | an `Option<_>` column must be filled (NOT NULL without default already is) |
| `email`, `url` | validated (`url` = absolute http/https only — never `javascript:`) |
| `min = n`, `max = n` | numbers: value; strings: length in characters |
| `slug_from = col` | left empty → slug of `col` on create, kept on edit |
| `format = date\|datetime\|time\|number\|currency` | rows also carry `{col}_display`, formatted in the request's language |
| `textarea` | multi-line input |
| `readonly` | shown, never editable (not a form field) |
| `hidden` | never shown, never in JSON |
| `private` | shown to signed-in users only — never on public pages or the public API, and not searchable/filterable/sortable there |

Hidden automatically: json/blob columns and **secret-looking names**
(`password`, `token`, `*_token`, `*secret*`, `*_hash`, `api_key`). They never
reach a page or an API response and can't be listed, searched or sorted.

Not form fields: the primary key, `owner`/`parent` columns, `readonly`,
hidden, `default = now`. A NOT NULL column that is none of those must be
fillable (form, owner, parent) or have a default — else it's a compile error
unless the model has `no_create`. On create, an omitted field with a default
gets the default. Decimal (`f64`) fields accept `1.5` and `1,5`.

### Relations (`#[orm(relation = fk)]` fields)

- A foreign-key **column** renders as a select of the related rows **the user
  may read** (`{target}.read` + the target's scope). A submitted id the user
  can't see is rejected (`invalid_option`) — a crafted form can't attach a
  row to something hidden. Mark FKs that must never change `#[ui(readonly)]`.
- On the **relation field**: `#[ui(show)]` embeds `{ id, title }` of the
  related row into every generated row under the field name;
  `#[ui(show(event))]` also embeds the related row's own `event` relation
  (`row.run.event.title`); `#[ui(list)]` = show + list column.
- The embedded `title` is the target's `title_field` — choose a column that
  is fine for anyone who can see the pointing row (not an email you'd hide).
- The target must be a `#[model]` (`disabled` is fine).

### Form error codes

`required`, `invalid_number`, `invalid_option`, `invalid_value`,
`invalid_datetime`, `invalid_email`, `invalid_url`, `too_short`, `too_long`,
`too_small`, `too_large`, `not_unique`, plus any your hooks push. Texts live
in `form_errors.{code}` (framework provides them; add yours to the app
locales).

## 3. Hooks — `impl ModelHooks for X` (with `#[model(hooks)]`)

Every method is optional. Hooks only **narrow** access: the role permission
is checked first and a hook can never grant what the role lacks. Write them
as plain `async fn`. Types come from `crate::*` (the prelude):
`ModelHooks, CurrentUser, Db, Cond, FormData, FormErrors, FieldError,
SaveCx, ActionCx, AppResult, AppError`.

```rust
impl ModelHooks for Event {
    /// Rows this user may see at all — ANDed into list, detail, update,
    /// delete and actions. None = all rows. Out of scope = 404.
    async fn scope(db: &Db, user: &CurrentUser) -> AppResult<Option<Cond>> {
        if user.is_admin() { return Ok(None); }
        let ids: Vec<i64> = EventManager::find()
            .filter(EventManager::USER_ID.eq(user.id()))
            .fetch_all(db).await?
            .into_iter().map(|m| m.event_id).collect();
        Ok(Some(Event::ID.in_(ids)))
    }

    /// Rows the public pages/API may show. None = all.
    fn public_scope() -> Option<Cond> { Some(Event::STATUS.eq(EventStatus::Live)) }

    /// May this user create (under `parent`, for a nested model)?
    async fn can_create(db: &Db, user: &CurrentUser, parent: Option<i64>) -> AppResult<bool> {
        Ok(user.is_admin())
    }

    /// Row-level locks: refused = 404 response, edit page renders read-only.
    async fn can_edit(&self, db: &Db, user: &CurrentUser) -> AppResult<bool> { Ok(!self.is_closed) }
    async fn can_delete(&self, db: &Db, user: &CurrentUser) -> AppResult<bool> { Ok(user.is_admin()) } // default: can_edit
    async fn can_act(&self, action: &str, db: &Db, user: &CurrentUser) -> AppResult<bool> { Ok(!self.is_closed) }

    /// Before parsing a create/update: normalize the raw form, return extra
    /// field errors. `cx.existing` is the stored row on update.
    async fn before_save(form: &mut FormData, cx: SaveCx<'_, Self>) -> AppResult<FormErrors> {
        let mut errors = Vec::new();
        if form.get("start") > form.get("end") {               // ISO dates compare as text
            errors.push(FieldError { field: "end", code: "before_start" });
        }
        Ok(errors)
    }

    async fn after_save(&self, db: &Db, user: &CurrentUser, created: bool) -> AppResult<()> { Ok(()) }
    async fn before_delete(&self, db: &Db, user: &CurrentUser) -> AppResult<()> { Ok(()) } // row still there: clean up files
    async fn after_delete(self, db: &Db, user: &CurrentUser) -> AppResult<()> { Ok(()) }

    /// Extra display fields on every generated row (sync, no DB). Prefer
    /// `#[ui(format = ...)]` for plain formatting.
    fn decorate(&self, row: &mut serde_json::Map<String, serde_json::Value>) {
        row.insert("badge".into(), if self.is_closed { "closed" } else { "open" }.into());
    }
}
```

`CurrentUser`: `id()`, `is_admin()`, `has_permission("x.y")`,
`role::<AppRole>()` (your enum back), `role_str()`.

Cheat sheet:

| need | use |
|---|---|
| "users only see their own rows" | `owner = user_id` (admins see all) or `scope` (strict, admins too) |
| "managers see only their events" | `scope` via the join table |
| "only published rows are public" | `public_scope` |
| "only admins create/delete" | `can_create` / `can_delete` |
| "locked once completed/paid" | `can_edit` (+ `can_create` with the parent id for children) |
| "derive a field / cross-field rule" | `before_save` |
| "send mail / log / sync after a change" | `after_save` / `after_delete` |
| "delete files with the row" | `before_delete` |
| "a button that changes a row" | `actions(...)` + `can_act` |

After-hooks run after the write is committed; an error there becomes the
response but does not undo the write.

## 4. Row actions

```rust
#[model(no_create, actions(fulfill, cancel), hooks)]
pub struct Order { /* ... */ pub status: OrderStatus }

impl Order {
    pub async fn fulfill(&self, cx: ActionCx<'_>) -> AppResult<()> {
        let id = self.id;
        update!(Order, cx.db, id == id; status = OrderStatus::Fulfilled).await?;
        Ok(())
    }
    // cancel likewise; `cx.user`, `cx.form` (posted fields) are available.
}

impl ModelHooks for Order {
    async fn can_act(&self, _action: &str, _db: &Db, _user: &CurrentUser) -> AppResult<bool> {
        Ok(self.status == OrderStatus::Pending)
    }
}
```

Route: `POST {base}/{id}/actions/{name}` (write permission, row in scope,
`can_act`). The generic pages show a button per allowed action (list rows
carry `_actions`, the edit page `actions`); labels: `models.{table}.actions.{name}`.
Afterwards the user returns to the row (or the list if the row left their
scope), or to `_back` (§6).

## 5. Nesting and many-to-many

**Nested** (`parent = col`, one level deep): a run belongs to an event.

```rust
#[model(parent = event_id, hooks)]
pub struct Run {
    pub id: i64,
    #[orm(references(Event, on_delete = cascade))]
    pub event_id: i64,
    pub name: String,
}
```

Routes `/{event base}/{event_id}/runs[...]`; permission base = the event's;
a run is only reachable when its event is visible to the user (on every path
— selects and foreign keys included); `event_id` comes from the URL, never
the form; templates get `parent` (`parent.row`, `parent.meta`). The parent's
edit page links its children.

**Many-to-many** (`link = owner_col`): a join table with exactly two foreign
keys; its primary key is `id` or exactly the two columns.

```rust
#[model(link = event_id, path = "managers", hooks)]
pub struct EventManager {
    #[orm(primary_key, references(Event, on_delete = cascade))]
    pub event_id: i64,
    #[orm(primary_key, references(User, on_delete = cascade))]
    pub user_id: i64,
}
```

Routes under the owner row: `GET {owner}/{id}/managers` (page),
`GET .../managers/candidates?search=` (JSON `{ rows: [{ id, title, linked }] }`),
`POST .../managers` with `id=` (add), `DELETE .../managers/{other_id}`
(remove). Viewing needs owner read + target read; changing needs owner write
+ target read, and only visible targets can be linked. Adding/removing runs
the join struct's own hooks: `can_create(db, user, Some(owner_id))`,
`after_save(created = true)`, `can_delete`, `before_delete`, `after_delete`.

## 6. Generated routes, pages and context

| route | permission | template (specific → generic) |
|---|---|---|
| `GET {base}` | read | `{ns}` → `fse/list` |
| `GET {base}/create`, `POST {base}/create` | write | `{ns}/form` → `fse/form` |
| `GET {base}/{id}`, `POST {base}/{id}` | read / write | `{ns}/form` → `fse/form` |
| `DELETE {base}/{id}`, `POST {base}/{id}/delete` | write | — |
| `POST {base}/{id}/actions/{a}` | write | — |
| `GET /{table}`, `/{table}/{key}` (`public_read`) | public | `{table}`, `{table}/detail` → `fse/public-*` |
| `GET /api/{table}`, `/api/{table}/{key}` (`api`) | public or read | JSON |
| link routes (§5) | see §5 | `{ns}/{segment}` → `fse/links` |

`{base}` = `/admin/{table}`, or `/{path}`, or nested
`{parent base}/{parent_id}/{segment}`. `{ns}` = base without the leading
slash, nested `{parent ns}/{segment}` (e.g. `event-manager/runs`).

- List query params: `search`, `page`, `per_page`, `sort` (a visible
  column), `dir=desc`, filter params.
- Success: create/update redirect to `{base}/{id}`; a form field `_back`
  pointing inside the model's own pages (e.g. `/my-runs`) redirects there
  instead — anything else is ignored (no open redirects). Validation errors
  re-render the form with `errors` and the submitted values.
- **Denied = 404.** The production stack answers 401/403 with a 404 page, so
  nobody learns a page exists. Not signed in = redirect to `/login`.

Context (keys every template can rely on):
- list: `meta`, `rows`, `total`, `total_count`, `page`, `per_page`,
  `total_pages`, `has_prev`, `has_next`, `prev_page`, `next_page`, `search`,
  `sort`, `desc`, `filters` (every filter param, `""` = unset),
  `can_create`, `parent`
- form: `meta`, `row`, `errors` (`[{ field, code }]`), `is_new`, `can_edit`,
  `can_delete`, `actions`, `parent`
- public pages: `meta` (public slice only), `rows` / `row`
- every page: `t` (translations), `lang`, `lang_prefix`, `nav`, `user`
  (when signed in), plus your `global_context_injector` keys
- `meta`: `table`, `base_path`, `title_field`, `list_columns`,
  `form_columns`, `filter_columns` (each: `name`, `widget`, `options`,
  `required`, `readonly`, `relation`, `display`, `filter`, `filter_params`),
  `actions`, `children`, `links`, `has_subpages`, `can_write`, ...

To restyle one page, create the specific template in the theme (e.g.
`theme/src/pages/admin/articles.astro`) using these keys. To restyle
everything, override the parent theme's components/styles (§8).

## 7. Hand-written code (`src/services/`)

Only for flows a model can't express (multi-step sign-ups, payment
callbacks, reports, PDFs, external APIs). Register in
`services::configure`; these routes win over generated ones on the same
path, so you can also replace a single generated route (e.g. a richer GET
list) while keeping the generated writes.

```rust
use crate::{AppData, AppResult, AppRole, AuthUser, RenderTplExt, find, json,
            actix_web::{get, web, HttpRequest}};

#[get("/reports/monthly")]
pub async fn monthly(data: web::Data<AppData>, req: HttpRequest, user: AuthUser<AppRole>) -> AppResult {
    user.require_permission("reports.read")?;          // always, first
    let rows = find!(Order, &data.db, user_id == user.claims.sub).await?;
    Ok(req.render_tpl("reports/monthly", &json!({ "rows": rows.len() })).await)
}
```

Rules:
- Every handler that touches data takes `AuthUser<AppRole>` and calls
  `require_permission`; scope by `user.claims.sub` where rows are owned.
- **Database access only through the ORM**: `find!`, `find_one!`,
  `find_page!`, `count!`, `insert!`, `update!`, `delete_rows!`, `X::fetch`,
  `X::find().filter(...)`. Never raw SQL, never `format!` into a query.
- Errors: return `AppError` / `?`; wrap foreign errors with
  `.context("what failed")`. Never `unwrap()` on input.
- Sessions: set the auth cookie only via `auth::session_cookie(&data, id, &role)`
  (after a role change), end it with `auth::logout_cookie`, revoke with
  `auth::revoke_sessions(db, user_id)` — never write `sessions_valid_after`
  or build a `token` cookie yourself.
- Redirect targets are your own literals — never echo a URL from input.
- Public free text: `text::strip_urls`; slugs: `text::slugify`; HTML
  outside templates: `tera::escape_html`; uploads: `uploads::save_upload` /
  `delete_upload` (size/type checked, served sandboxed); QR: `qr::svg_data_uri`;
  PDF: `pdf` (feature); mail: `send_mail` with a template.
- Config comes from `data.config` (validated at boot) — never `env::var` in
  a handler. Secrets are `SecretString`; never log them.
- Logging: `info!`/`warn!`/`error!` with fields; never log tokens, cookies,
  query strings or bodies.

## 8. Frontend (themes)

Pages are Astro files compiled to Tera templates by `fse-ssr`; the server
renders them with the context above (HTML is autoescaped). The default theme
(`fse-theme-default`) renders every generated page, auth page and email —
**most apps need no frontend code**.

For custom design add a child theme in `theme/` (as the starter does):
`theme.json` `{ "name": "<app>", "parent": "fse-theme-default" }`,
`package.json` with `astro`, `fse-ssr`, `fse-theme-default`, tailwind;
`astro.config.mjs` with `fseSsr({ locales: "../locales", defaultLocale: "en" })`;
then in `src/lib.rs`:

```rust
pub static THEME_DIR: Dir<'_> = include_dir!("$CARGO_MANIFEST_DIR/theme/dist");
pub fn themes() -> Vec<Theme> {
    vec![Theme::embedded(&fse_theme_default::DIST),
         Theme::embedded(&THEME_DIR).dev_server("http://localhost:4321")]
}
```

A file at the same `src/` path as the parent's replaces it everywhere
(`src/components/SidebarLinks.astro`, `src/styles/global.css`); import the
parent's originals as `@parent/...`. Pages under `src/pages/` are templates
by path (`pages/admin/articles.astro` → template `admin/articles`).

In `.astro` files, read context with `const { t, rows } = ssr<MyType>();`.
These compile to Tera, which has limits — fse-ssr errors at build time when
you hit one:
- No grouping parentheses: `(a || b) && c` fails → compute a flag
  server-side (or in `decorate`).
- `??` is a Tera default (only for **missing** keys, not nulls) and is
  rewritten even in frontmatter — for a build-time fallback between two
  values use a plain `if`.
- String literals in expressions can't contain quotes/apostrophes.
- No Tera filters from `.astro` — use `{col}_display` (`#[ui(format)]`) or
  `decorate`.
- `t` is typed from the app's locale files only; framework keys
  (`form_errors`, `model_ui`) need a cast:
  `(t as unknown as { form_errors: Record<string, SsrValue<string>> }).form_errors`.
- Never add inline event handlers (`onclick=`): the CSP nonce can't cover
  them. Use `<script>` blocks (bundled, nonce-stamped).
- Everything in a page's context ships to the browser as JSON
  (`__fse-props__`): don't put secrets or bulk data in it.
- Attribute values are escaped (`/` → `&#x2F;`) — assert on fragments in tests.

## 9. Testing

```rust
use full_stack_engine::testing::TestApp;
use my_app::AppRole;

#[actix_web::test]
async fn authors_edit_only_their_articles() {
    let app = TestApp::new(my_app::app()).await;          // production stack, in-memory DB
    let alice = app.user("alice@test.dev", AppRole::Author).await;
    let bob = app.user("bob@test.dev", AppRole::Author).await;

    let res = app.post("/admin/articles/create").as_user(&alice)
        .form(&[("title", "Hello")]).send().await;
    assert_eq!(res.status, 302);
    let id = res.created_id().unwrap();

    let res = app.get(&format!("/admin/articles/{id}")).as_user(&bob).send().await;
    assert_eq!(res.status, 404);                          // denied = 404
}
```

`TestApp` builds the app exactly as `cargo run` does (all middleware, route
order, error pages, CSP, strict template loading, model consistency check)
over a migrated in-memory database. `app.user(email, role)` creates a signed
in user (password `TEST_PASSWORD`; call again after a role change);
`app.get/post/delete(uri)` → `.as_user(&u)`, `.form(&[..])`, `.json(&v)`,
`.header(..)`, `.from_ip(addr)` → `.send()` → `TestResponse { status,
headers, body }` with `.location()`, `.created_id()`, `.json()`. Seed rows
with `insert!(Model, &app.db, ...)`.

Test every rule you declare: a scope, a lock, an action guard, a validation.

## 10. Security — what the framework guarantees, what you must not undo

Guaranteed by default:
- Every generated endpoint checks the role permission, then the model's
  scope/owner/parent, then the row hooks — in one code path.
- Out-of-scope rows are 404; denied pages render as 404.
- Foreign keys and links only accept rows the user may read.
- Secret-looking columns, `hidden` and json/blob columns never leave the
  server; `private` columns never reach anonymous users; public pages get no
  admin metadata.
- Owner/parent columns are never taken from a form.
- Parameterized SQL only (the ORM); LIKE input escaped; page sizes clamped.
- Autoescaped templates; per-request CSP nonce; hardened headers; HttpOnly +
  SameSite=Strict (+Secure in prod) session cookie — the CSRF defence for
  every POST; Argon2 passwords; per-IP rate limits; sessions revocable.
- `_back` redirects only inside the model's own pages.
- Config validated at boot; secrets can't be logged.

You must not:
- write raw SQL, or build queries/HTML/URLs by string concatenation;
- skip `require_permission` / ownership in a hand-written handler;
- re-implement CRUD in `services/` (you lose every guarantee above);
- render user input with `| safe`, or put it in `href` unless validated
  (`#[ui(url)]`);
- set cookies, sessions or roles by hand;
- loosen CSP (inline handlers, `unsafe-inline`), CORS, or cookie flags;
- log or render secrets, tokens, password hashes;
- store files outside `uploads::save_upload` or serve private files
  publicly (`data/` is private, `uploads/` public);
- edit applied migrations or the `.sqlx/` cache by hand.

## 11. Batteries (don't add a crate for these)

`auth_module` (login, registration, verification, password reset, settings,
user admin, first admin from `ADMIN_EMAIL`/`ADMIN_PASSWORD`), i18n
(`Hardcoded`/`Domain`/`Path` language modes), `send_mail` +
email templates, `cron` jobs (`.cronjobs(...)`), `uploads`, `qr`, `pdf`
(feature), `forms` (`empty_as_none`, `parse_decimal`), `text` (`slugify`,
`strip_urls`), Tera filters `date`/`datetime`/`time`/`number`/`currency`,
CORS (`CORS_ALLOWED_ORIGINS`), OpenAPI + `/api/docs` (`.api_docs(...)`),
`/healthz` + `/readyz` + `--healthcheck`, tracing/OTLP/Sentry via env vars.

Environment (`.env`): `ENV`, `DATABASE_URL`, `DOMAIN`, `PROTOCOL`, `PORT`,

`SENTRY_DSN`. The app refuses to boot with an invalid configuration and
